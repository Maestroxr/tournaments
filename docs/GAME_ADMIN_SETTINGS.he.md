# ניהול הגדרות לפי סוג משחק

עודכן: 11.10.2026. ההיקף אושר בשיחה ב״תעשה את זה״. זהו מימוש מקומי; מיגרציה, בדיקות, build, מובייל ופריסה לא הורצו.

## מפת הניהול

העמוד הקיים `/direct-play` באדמין נשמר. הניווט הוא דרך Vue Router עם `?section=...`; `quick` מפנה לתצוגת money ו־`formats` לתצוגת match לצורך תאימות לקישורים ישנים.

| אזור | מקור הנתונים | משמעות |
|---|---|---|
| Match | format_profiles.match | זמינות, ציבורי וחיפוש יריב, יעדים, שעונים, הכפלות, קובייה, סכומים ועמלה |
| חבר | friend_rules + friend_game_fee | כללים עצמאיים; כל שחקן משלם מחיר לנקודה × יעד; אין פרס למנצח |
| הכפלות | format_profiles.money + money_time_control | שעון קבוע; הכפלה לפי בחירת השרת, Jacoby, סכומים ועמלה; חשיפה דינמית לפי יתרות |
| Open Sage | practice_rules + ai_game_fee | מחיר, יעדים ושעונים לבחירת השחקן |
| טורנירים | tournament_fee_percent + הגדרות הטורניר עצמו | עמלה כללית וקישור לניהול; השעון נבחר בכל טורניר |
| כללי | enabled + coin_grant_* | הפעלה כללית של המשחקים הישירים ובונוס המטבעות |
| מתקדם / תאימות | game_rules, stake_amounts, head_to_head_fee_percent | נתונים ישנים נשמרים; אינם מנהלים יצירת משחקים חדשים |

אפשרויות זמן: none, normal, fast, slow. האדמין מציג לכל משחק רק פקדים שמשפיעים על המסלול שלו. הכפלות משתמשות בשעון הקבוע גם אם הלקוח שולח שעון אחר. השדות ההיסטוריים max_cube ו־loss_limit_multiplier של money נשמרים במסד; הם אינם מוצגים כפקדים לחישוב הדינמי. נוסחאות החיוב וההתחשבנות לא השתנו.

משחק חבר נשאר בפורמט match ובחוזה חתום. הגדרות יעדים, שעונים, זמינות והכפלות שלו עצמאיות; גם תקרת הקובייה שלו מועתקת במעבר ומנוהלת בנפרד מפרופיל match. הפעלה כללית enabled עדיין חלה עליו. ההפרדה אינה משנה חוזים של שולחנות קיימים.

## שמירה וטיוטות

לכל אזור טיוטה וחיווי שינויים משלו. PUT ל־/api/admin/direct-play/settings כולל section ורק את שדות האזור. פרופיל חלקי מתמזג עם הפרופיל המעודכן בתוך טרנזקציה ונעילת שורת ההגדרות; שדות שאינם שייכים לאזור נדחים. בקשות ישנות ללא section נשארות נתמכות.

שמירה או רענון אינם מחליפים טיוטות אחרות. שמירה כפולה נחסמת; תשובות אחרי פירוק העמוד אינן משנות מצב. שגיאות שדה מוצגות ליד הפקד, וקיימת התראה לפני עזיבת העמוד עם טיוטות. רענון הניטור אינו טוען שוב הגדרות.

## מעבר נתונים

המיגרציה החדשה `tournaments.0035_game_mode_settings` מוסיפה friend_rules, practice_rules ו־money_time_control:

- חבר מקבל עותק של היעדים, השעונים, תקרת הקובייה וההכפלות בפרופיל match הקיים. זמינותו משמרת enabled וגם private של הפרופיל הקודם. גם יעדים לא סטנדרטיים בטווח 1–25 נשמרים.
- השעון הקבוע של הכפלות מקבל normal אם היה זמין, אחרת את השעון הראשון ברשימה הקיימת.
- Open Sage מתחיל עם היעדים והשעונים הנתמכים שהיו בקוד.
- מחירים, עמלות, פרופילים, נתוני Legacy וחדרים קיימים אינם משוכתבים.

לפני הפעלת גרסת השרת החדשה יש להחיל את המיגרציה בסביבת היעד המאושרת. היא טרם הורצה כאן. יש לעדכן את השרת ואת שני ממשקי Vue יחד; ממשק אדמין ישן אינו מנהל את ההגדרות הנפרדות החדשות.

Open Sage בודק כללים לפני יצירת רכישה חדשה. אפשרות שהוסרה מחזירה rules_changed בלי חיוב או הכנת חדר; הממשק מרענן את האפשרויות. רכישה קיימת שומרת את האפשרויות השמורות ואת מניעת החיוב הכפול.

## אימות

TypeScript, ESLint ו־Oxlint ממוקדים עברו בשני ממשקי Vue. תחביר תשעה קובצי Python עבר באמצעות ast.parse. Ruff לא זמין ב־Python המקומי. אין טענת הצלחה ל־tests, build, מיגרציה או דפדפן.

פקודות להרצת המשתמש בלבד, כל אחת מתוך התיקייה שצוינה:

מתוך `backgammon-tournaments-backend/tournaments`, בסביבת Python התקינה של הפרויקט:

```powershell
python manage.py test frontend.test_game_mode_settings frontend.test_game_formats frontend.test_head_to_head gamelink.test_practice
```

מתוך `backgammon-tournaments-backend/admin-frontend`:

```powershell
pnpm exec vitest run src/pages/DirectPlayView.spec.ts --environment jsdom
pnpm build
```

מתוך `backgammon-tournaments`:

```powershell
pnpm exec vitest run src/views/__tests__/PracticeView.test.ts src/stores/__tests__/practice.test.ts src/components/__tests__/DirectGameAccess.test.ts --environment jsdom
pnpm build
```

להחלת מיגרציה בסביבת פיתוח או יעד שאושר, לאחר בדיקת המיגרציות התלויות; זו אינה פקודת פריסה:

```powershell
python manage.py migrate tournaments
```

בדיקות קבלה ידניות: להגדיר ללא שעון רק לחבר ולוודא שהוא אינו מוצע ב־Match; לקבע fast בהכפלות ולוודא שהחדר מקבל fast; להסיר none ב־Open Sage ולוודא רענון ואכיפה; לשמור טיוטה באזור אחד בזמן עריכה באזור אחר; לבדוק רענון, שמירה כפולה, שגיאות שדה, ניטור וביטול. לבדוק עברית ואנגלית, RTL, מקלדת, מובייל באורך ובנוף ומחשב. בחדר קיים יש לוודא שהשעון והחיוב נשמרים.
