# צמצום העבודה תחת נעילות הרשמה והצטרפות

שינוי מקומי שאושר בשיחה ב־07.10.2026. המשתמש אישר גם commit ו־push; אין אישור פריסה.

ב־`api_join` מכינים את זהות המשתתף לפני נעילת הטורניר. מצב הרשמה, קיבולת והשתתפות נבדקים תחת הנעילה; החיוב וההוספה נשארים אטומיים. עזר השמירה הופרד מבדיקות העזר כדי לא לבצע אותן פעמיים. התשובה נבנית אחרי שחרור הנעילה.

ב־`api_withdraw` מחפשים את המשתתף לפני הטרנזקציה ובודקים מצב טורניר באמצעות פרסום וקיום משחקים. החזר, הסרה ועדכון הרשמה נשארים יחד תחת נעילת הטורניר וההרשמה.

ב־`api_head_to_head_join` בדיקת משחק פעיל מתבצעת אחרי נעילת שני החשבונות לפי מזהה. שני הפורמטים משתמשים באותו עזר. שליפת השולחן עם המארח נועלת את השולחן בלבד באמצעות `of=('self',)`, ובניית תשובת הצלחה מחוץ לטרנזקציה. נעילת ההגדרות המשותפת נשארה; השפעתה על העומס לא נמדדה.

ב־`api_admin_tournament_attendees` הטרנזקציה נמצאת בתוך הפונקציה הפנימית. הרשאת מנהל, פענוח JSON ובדיקת מבנה הקלט והפעולה מתבצעים לפניה; GET ו־CSV נשארים ללא טרנזקציה. ההוספה והעדכון הופרדו לעזרים. מצב הטורניר, קיבולת והרשמות נבדקים תחת הנעילה; הרשמות והשתתפויות נשלפות בקבוצות. חשבונות בהחזר או שחזור קבוצתי ננעלים לפי מזהה. שגיאות יוצאות מהטרנזקציה לפני ההמרה לתשובה, כך שכשל בשחקן השני מבטל גם את רישום וחיוב הראשון. רשימת המשתתפים והסיכום נבנים לאחר commit.

## אימות

נבדקו תחביר Python ו־Ruff. בשלושת קובצי הבדיקות החדשים אין הערות lint; תשע הערות קיימות ב־API ובעזר הפורמטים נותרו ללא הערות חדשות. ההבדלים ב־`api_urls.py` הם עיצוב קוד בלבד, כפי שאומת בהשוואת AST.

הבדיקות נוספו אך לא הורצו, בהתאם לחלוקת העבודה בפרויקט. גם build, שרת, מדידת זמני אמת ובדיקת מקביליות PostgreSQL לא הופעלו. בדיקות סטטיות אינן הוכחה לשיפור ביצועים או לתקינות בפרודקשן.

מפעילים מתוך תיקיית `tournaments` בסביבת Python של השרת:

```powershell
python manage.py test frontend.test_tournament_join frontend.test_tournament_lifecycle frontend.test_attendee_transactions frontend.test_attendee_operations frontend.test_attendee_funding frontend.test_head_to_head_join frontend.test_head_to_head frontend.test_game_formats frontend.test_search_lifecycle
```

הבדיקות החדשות מכסות חיוב יחיד, החזר יחיד, קיבולת, סגירה ידנית, משחק פעיל, גבולות הטרנזקציה ו־rollback של פעולה קבוצתית. בדיקת `FOR UPDATE OF` מופעלת רק במסד שתומך בכך; היא אינה תחליף לבדיקת מקביליות עם חיבורים נפרדים ב־PostgreSQL.
